# NIDS 特征语义说明（当前实现）

本文描述 `backend/pcap_parser.py` 与 `backend/traffic_generator.py` 当前采用的 9 维特征。**字段名沿用既有模型接口，不代表从 PCAP 中一定能直接观测到同名业务语义。**

| 特征 | 当前计算方式 | 解释与限制 |
|---|---|---|
| `duration` | 会话中最晚包时间 − 最早包时间，最低取 `0.001` 秒 | 是抓包观察到的时间跨度；若抓包从会话中途开始或提前结束，不等于真实连接完整持续时间。 |
| `protocol_type` | TCP=`0`，UDP=`1` | 模型编码。当前解析器只处理 TCP/UDP；虽然编码表预留 ICMP=`2`，但 ICMP 包目前会被跳过。 |
| `src_bytes` | 首次观察到的包方向上的 IP payload 字节数之和 | “src”指该会话首包的源端，不一定是客户端。IP payload 通常包含 TCP/UDP 头及其后数据，不是纯应用层字节数。 |
| `dst_bytes` | 与首包方向相反的数据包 IP payload 字节数之和 | 与 `src_bytes` 使用同一方向基准。 |
| `packet_count` | 聚合进会话的 TCP/UDP 包数量 | 不包含非 IP、ICMP 等当前未处理的包。 |
| `failed_logins` | 当前 PCAP 中该源 IP 发往 21、22、3389 目的端口的包命中次数 | **并非真实失败登录次数**；只根据端口号近似，无法区分成功/失败登录，也可能把重传或普通业务包算进去。为兼容既有训练模型和 API，暂时保留旧字段名。 |
| `num_unique_ports` | 当前 PCAP 中该源 IP 访问过的不同目的端口数量 | 是源 IP 级、整个抓包文件范围内的统计，并非单条连接自身的端口数量。抓包窗口不同，数值也会不同。 |
| `syn_rate` | 会话内带 SYN 标志的 TCP 包数 ÷ TCP 包总数 | SYN 重传也会计入；这是流量特征，不是独立的 SYN Flood 判定。UDP 连接为 `0`。 |
| `bytes_per_packet` | `(src_bytes + dst_bytes) / packet_count` | 平均每个已统计包对应的 IP payload 字节数。 |

## 会话聚合边界

- TCP/UDP 以双向端点（IP、端口）和协议组成基础键，因此同一五元组的请求与响应会聚合到同一条记录。
- TCP 观察到 RST，或观察到两个方向的 FIN 后，再遇到新的 SYN（且没有 ACK）时，会创建新会话。若抓包缺失 FIN/RST、会话中途开始、SYN 丢失，仍可能无法准确区分同一五元组的多次会话。
- UDP 没有 TCP 式的连接建立/关闭标志；当前同一双向端点键在整个 PCAP 内会聚合，尚未实现基于空闲超时的 UDP 流切分。
- 解析器目前不做 TCP 流重组、分片重组、应用层协议解析或登录日志关联。

## 模型使用注意

这 9 维特征是项目自定义的连接级特征，借鉴连接记录式 IDS 的思路，但不等于 CICIDS2017 等数据集原始特征的同名字段。接入公开数据集时，应编写独立适配器并逐列核对语义、单位、聚合窗口和标签，不能仅凭字段名相似就直接拼接训练。
